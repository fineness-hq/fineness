B. PROJECT REPORT (REPORT.MD SPECIFICATION)

# FINENESS — PROJECT REPORT & APPLICATION ARCHITECTURE

1. PROJECT DESCRIPTION
Fineness is a monthly ranked register of venues that launch or trade
tokenized assets. Each venue receives a fineness score from 0 to 1000,
derived from five weighted criteria (asset 30, traction 25, transparency
20, compliance 15, durability 10). The register prices the gap between
RWA marketing and actual backing: most venues sell memecoins while the
real asset appears only as the pairing. A pure build-time pipeline pulls
public figures into hashed snapshots and freezes permanent edition pages
plus verbatim JSON. Live: 2 frozen editions, 10 venues each, peak 745
(Pons, 14k) — nothing clears 18 karat.

2. CORE CAPABILITIES
- Deterministic Scoring: weighted mean x 100, rounded once; reader parity
  between build output and browser recompute.
- Shareable Reweighting: five sliders + presets serialize into ?w= URLs
  with before-first-paint ranking and a custom-weights banner + reset.
- Frozen Editions: content-hashed snapshots, alphabetical tiebreaks,
  house-weight deltas, struck dates, correction notes with dual sign-off.
- Editorial Integrity: no paid placement path, resolving sourceIds,
  null discipline, never described as audit or rating.
- Full Autonomy: cron + AI review inside policy caps + gates; --strict
  halts on any smell; humans only on exception.

3. END-TO-END APPLICATION FLOW (USER & SYSTEM WORKFLOW)
[Step 1: Monthly run]
- Cron day 1 (or npm run monthly): pull providers -> atomic snapshot ->
  hash -> AI review (capped) or carry -> validate -> atomic edition ->
  tests pass -> commit+push -> Vercel deploys.
[Step 2: Read]
- Visitor opens https://fineness.tech, reads the latest frozen
  edition: hero proof bar, telemetry, ticker, register, comparison tables.
[Step 3: Reweight]
- Sliders/presets recompute the ranking live; the URL updates; opening
  that URL reproduces the sender ranking before first paint.
[Step 4: Inspect]
- Expand any venue: per-criterion scores with rationale, key figures,
  contracts with copy, official links. Dossier pages show cross-edition
  history with sparkline.
[Step 5: Build on it]
- Fetch /editions/<id>.json: venues, scores, bands, ranks, metrics,
  sources — the same data the page renders.
